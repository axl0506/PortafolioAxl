Case Study: Optimización de Script de Auditoría Registral (SUNARP)

Reestructuración de Package PL/SQL eliminado Full Table Scans y cuellos de botella.

Original: 12.4s Optimizado: 0.18s (-98.5%)
BEFORE (Incapacidad de Escalar) High CPU Cost 
-- Consulta ineficiente en Big Data
SELECT p.id_partida, p.num_partida, n.nombre_notario
FROM tbl_partidas_registrales p
LEFT JOIN tbl_notarios n ON p.cod_notario = n.cod_notario
WHERE TO_CHAR(p.fecha_registro, 'YYYY') = '2025'
  AND UPPER(p.estado) LIKE '%ACTIVO%';
-- Problema: Anula el uso de índices B-Tree por funciones TO_CHAR y UPPER.
AFTER (Optimizado con SARGable Query) Index Range Scan 
-- Script Reestructurado por Nilger Coronado
SELECT /*+ INDEX(p idx_partidas_fecha_est) */ 
       p.id_partida, p.num_partida, n.nombre_notario
FROM tbl_partidas_registrales p
INNER JOIN tbl_notarios n ON p.cod_notario = n.cod_notario
WHERE p.fecha_registro >= TO_DATE('2025-01-01', 'YYYY-MM-DD')
  AND p.fecha_registro < TO_DATE('2026-01-01', 'YYYY-MM-DD')
  AND p.estado_id = 1; -- Filtrado numérico indexado
